# 复测协议

## 一、先分清：什么可客观验证，什么不能（诚实边界）

命理技能的产出分两层，验证性质完全不同，复测必须分层对待：

| 层 | 内容 | 可验证性 | 验证方式 |
| :--- | :--- | :--- | :--- |
| **L1 排盘层** | 四柱、节气、农历、大运、神煞 | **完全可客观验证** | 与权威数据/独立实现比对，有确定答案 |
| **L2 解读层** | 格局、强弱、用神、运势倾向 | **无唯一标准答案** | 只能验证：规则自洽性、结论稳定性、依据可回溯性 |
| **L3 交付层** | 格式、措辞、伦理、免责 | 可机械核对 | 质量核验清单（commands/50） |

**不许做的**：把解读层当成排盘层验证——"这个预测准不准"在科学上无法用历史案例证明（后见之明偏差：事后总能为任何人生找到"符合"的解读）。本技能的复测目标是 **排盘零错误 + 解读有据可溯、稳定可重复、合规不越界**，不是"预测准确率"。

## 二、行业标准是什么

### L1 排盘层：有国家标准（事实标准）

**GB/T 33661-2017《农历的编算和颁行》**（中国科学院紫金山天文台归口）定义了排盘的物理依据：

- 二十四节气 = 太阳地心视黄经等于 15° 整数倍的**时刻**（不是日期）；
- 时刻以北京时间（UTC+8，东经 120° 标准时）表示，精确到秒；
- 农历编算用定气定朔（冬至所在月为十一月、无中气之月置闰）。

本技能口径（`rules/1-排盘口径.md`）完全对齐该标准。权威对照数据使用「中国历法公共数据集」（Zenodo #22820072，CC BY 4.0）：JPL DE421 星历独立计算 1900-2052 年全部 3,672 条节气时刻，与紫金山天文台 2026 年官方值逐条比对最大差 21 秒、分钟取整全部一致（见 `tests/testdata/verification_2026_vs_zijinshan.csv`）。

### L2 解读层：没有行业标准，只有流派规则

命理解读无国家认证体系、无统一考试、无"标准答案"。同一命盘，子平格局法、盲派、新派对格局强弱可能有不同判断——这是流派差异，不是谁错。因此解读层复测只对**本技能自己的规则体系**做一致性验证：

- **规则自洽**：结论必须能由 `rules/2-十神详解.md` 的规则表推导出来；
- **稳定可重复**：同一命盘多次解读，关键定性（格局名、身强弱、用神五行）必须一致；
- **有据可溯**：每条结论能回指命盘依据与典籍卡片（`rules/5-证据与引用规则.md`）。

### L3 交付层：伦理底线（技能自设标准）

伦理红线（不测生死、不恐吓、不替决策）由 `rules/4-解盘原则.md` 规定，交付前逐条机械核对——这条比任何"准确性"都重要。

## 三、三层复测体系

### L1 排盘层复测（客观，三道独立证据链）

| 证据链 | 内容 | 命令 | 通过标准 |
| :--- | :--- | :--- | :--- |
| ① 黄金锚点 | 立春年界、早晚子时、大运顺逆、农历阳历同盘等高危边界 | `python tests/test_pai_pan.py` | 28 用例全过（秒级） |
| ② 独立实现交叉 | 与另一独立算法实现（jinchenma94，Meeus 算法）18 例四柱比对 | 同上（内嵌） | 完全一致 |
| ③ 权威数据全量 | 1900-2052 节气 3,672 条、换柱边界 1,836 条、日柱 55,883 天、立春年界 153 条 | `python tests/test_authority.py` | 6 组全过（约 40 秒），快检 `--quick`（秒级） |

**运行频率**：日常回归跑 ①②；口径变更、引擎（lunar_python）升级、发版前必跑 ③ 全量。

**实测精度基线**（2026-10 复测记录，写死供后续回归对比）：
- 节气时刻与权威数据最大偏差 **46 秒**，3,672 条全部在 1 分钟内；
- 日柱 55,883 天与权威干支对照表**零偏差**；
- 换柱边界 ±15 分钟窗口内月柱切换**零错误**。

### L2 解读层复测（稳定性 + 自洽性）

**黄金盘**：1990-05-15 12:00 男（庚午/辛巳/庚辰/壬午），本技能规则推导的基准定性如下（供稳定性回归对照，**非行业唯一答案**）：

| 定性项 | 基准 | 推导依据（rules/2 规则链） |
| :--- | :--- | :--- |
| 格局 | 七杀格 | 月支巳藏丙戊庚，余气庚金透年干为比肩不取格（取格细则）→ 取月令本气丙火七杀为格 |
| 强弱 | 身弱（杀重身轻） | 巳月失令、地支巳午午三火克金；仅得势（年庚月辛比劫透）＋弱得地（日坐辰土湿印）；火炎金弱 |
| 用神 | 土（印）化杀生身为主；金（比劫）扶身、水（壬）调候为辅 | 杀重身轻取印通关＋身弱取比劫；巳午月燥金喜水润（TH-0003），时干壬水调候在位 |
| 忌神 | 火（官杀）、木（财生杀） | 克身、生杀之物 |
| 层次 | 中上 | 杀印相生倾向（辰土湿印化杀＋壬水调候），大运壬午火旺克身，癸未（未土印）、甲申（申金禄）渐得帮身 |

**稳定性复测方法**：同一黄金盘完整解读 3 次，检查 5 项关键定性（格局名/强弱结论/用神五行/忌神五行/层次档）是否一致；不一致即视为解读层不稳定，回到 `rules/2-十神详解.md` 检查规则表述是否存在歧义。

**自洽性复测方法**：任意命盘的解读结论逐条反查——每条结论的命盘依据能否在排盘输出中找到？引用卡片是否存在且适用前提满足？（执行 `commands/50-交付前质量核验.md` 的第 8-11 项）。

### L3 交付层复测（合规）

交付前逐条执行 `commands/50-交付前质量核验.md` 全部 24 项；伦理红线 4 条（第 12-15 项）**零容忍**，任一条不通过即退回修订。

## 四、历史名人怎么用（含王侯将相：来源是强证据，解读不是）

### 4.1 先纠正一个常见误区：来源强 ≠ 解读可验证

王侯将相的生辰**来源质量确实高**——正史实录、宗人府玉牒、起居注记录帝王生辰时刻，比网传名人生时（多为野史倒推）可靠一个量级。但"强证据"要分清证明哪一层：

| 用途 | 王侯将相案例的证明力 |
| :--- | :--- |
| 证明**生辰记载**（某人生于某日某时） | 强（实录/玉牒为信史，见 4.2 分级） |
| 证明**排盘正确**（该生辰排出什么柱） | 不需要——L1 已有天文级权威数据全量验证，比任何名人案例都硬 |
| 证明**解读准确**（命盘断语与人生吻合） | **不成立**，见 4.4 三条致命缺陷 |

### 4.2 生辰来源分级

| 等级 | 来源 | 示例 | 采信 |
| :--- | :--- | :--- | :--- |
| A 级 | 正史实录、宗人府玉牒、官方档案载明的出生**日期** | 帝王生卒、溥仪出生日 | 可作排盘输入 |
| B 级 | 档案/传记流传的出生**时刻**（常有异说） | 乾隆"子时"说有午时异说 | 采信但必须标注异说与版本 |
| C 级 | 网传野史、为套事迹倒推的"名人八字" | 多数网络命例 | **一律不采信** |

### 4.3 可用的用途（弱证据，照常用）

- **演示与教学**：真实命例便于展示完整流程（见 `tests/名人案例.md`，含帝王命例）；
- **三柱抽查**：1900-2052 年间名人的出生年月日可对拍权威干支对照表（数据验证，与解读无关）；
- **排盘换算验证**：A 级日期 + B 级时辰（如帝王玉牒时刻）可作为"农历→公历→节气→四柱"换算链的额外抽查样本。

### 4.4 为什么王侯将相证明不了解读准确（三条致命缺陷）

1. **无对照组 + 幸存者偏差**：史册留名者皆"富贵有成就"，解读说"大贵之命"永远"命中"；史书里不会有"同八字但平庸一生"的对照样本。命盘与结局的样本全部来自成功者，任何解读规则都会被"验证"成功。
2. **后见之明污染（循环论证）**：结局已知，解读必然向结局靠拢——一个命盘有十神×柱位×神煞×刑冲合害×大运×流年成百上千个可解读要素，总能挑出与已知结局相符的组合。知道结局再"验证"，验证力为零。
3. **同盘不同命 + 不可证伪**：帝王出生的同一时刻，全国同时出生者成千上万，命运各不相同——命理界自己以"风水、阴德、时代"补足解释。既然八字不决定一切，任何人生结局都无法**证伪**八字解读；不可证伪的命题无法被历史案例验证。对 AI 技能还多一条：模型训练数据里本就充斥着这些名人的命理分析文章，对照必然"吻合"。

### 4.5 王侯将相唯一能产生验证力的用法：盲测（可选增强实验）

设计如下（排除"先看结局再编解读"的污染）：

1. 选取 3-5 个历史人物（帝王/名将/富商/文人/平民，A 级日期来源），只准备**匿名命盘**（不附姓名生平）；
2. 技能按完整流程解读，**先写出** 3 个可核对判断：层次高低（贵/富/平）、职业倾向、性格显隐；
3. 揭晓对照，记录命中/未命中；
4. 同一盘重复 3 次，检验判断稳定性。

**结论上限（必须诚实）**：盲测只排除后见之明，仍有样本量小（N=3-5）、训练数据污染、贵格特征早已写进命书（先验）三重局限——因此盲测结果的最高效力是"**解读一致性演示**"，不能上升为"预测有效性证明"。真正能测预测力的只有大规模**事前**预测 + 长期随访（超出历史人物与技能范畴）。

**名人案例使用规范**（写入 `examples/`）：
1. 必须标注出生日期来源等级（A/B/C，见 4.2）与**时辰置信度**；
2. 时辰存疑时只排三柱或标注"时柱为假设值，仅供演示"；
3. 解读只作流程演示，文末声明"命例解读不构成对已故人物的评判，亦不构成准确性证明"。

## 五、可重复验证性设计（为什么能"谁跑都一样"）

1. **确定性**：排盘是纯函数——同一输入必然同一输出，无随机性、无网络依赖、无环境时区影响（时区硬编码北京时间）；
2. **数据固化**：权威对照数据随技能仓库一起保存（`tests/testdata/`，含许可证），不依赖任何在线服务，任何时候任何机器跑结果一致；
3. **测试即文档**：锚点写进 `pai_pan.py` 头部 docstring、黄金测试、`rules/1-排盘口径.md` 锚点表三处，四处一体；
4. **版本化变更**：口径变更必须同步脚本锚点、`rules/1-排盘口径.md`、`rules/3-神煞规则.md`、黄金测试四处（`rules/翻车预防清单.md` 第一条），任一测试失败即阻断；
5. **解读层最小可复测**：用黄金盘基准定性做稳定性回归——解读层无法做"标准答案比对"，但可以做"自身重复性比对"。

## 六、复测操作手册

```bash
# 日常回归（每次改脚本/规则后）
python tests/test_pai_pan.py

# 权威全量复测（发版前/引擎升级/口径变更）
python tests/test_authority.py            # 约 40 秒
python tests/test_authority.py --quick    # 秒级快检

# 解读层稳定性（人工，3 次黄金盘解读对照基准定性）
# 交付层合规（人工，commands/50 清单逐条打勾）
```

**复测通过门槛**：L1 全部测试通过 + L2 黄金盘 5 项定性 3 次一致 + L3 清单零遗留，三者齐备方可视为"复测通过"。
